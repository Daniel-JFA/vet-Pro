TAREA 2: Crear endpoint de registro de clínica en el backend
────────────────────────────────────────────────────────────────────────────────

Crear archivo nuevo:
  /home/djfa/Dev/projects/Propios/Vet/vetpro-backend/src/routes/clinic.routes.ts

El endpoint es:
  POST /api/v1/clinics/register  (público, sin auth)

Body JSON esperado:
{
  "clinicName": string (requerido),
  "nit": string (opcional),
  "phone": string (requerido),
  "email": string (requerido),
  "address": string (requerido),
  "city": string (requerido),
  "branchName": string (requerido),
  "branchAddress": string (requerido),
  "adminFirstName": string (requerido),
  "adminLastName": string (requerido),
  "adminEmail": string (requerido),
  "adminPassword": string (requerido, mínimo 8 caracteres)
}

Lógica del endpoint (todo en una transacción Prisma):
1. Verificar que no exista una clínica con ese email → 409 si ya existe
2. Verificar que no exista un usuario con ese adminEmail → 409 si ya existe
3. En una sola transacción:
   a. Crear Clinic con plan 'starter'
   b. Crear Branch principal (sede) con los datos de branch
   c. Hashear adminPassword con bcrypt (rounds: 12)
   d. Crear User con role 'admin', vinculado a la clinic y branch
4. Devolver JWT + user + clinic (mismo formato que POST /auth/login)

Usar el mismo patrón de signToken que en auth.routes.ts.
Importar bcrypt, jwt, prisma.
JWT_SECRET debe fallar con process.exit(1) si no está definido (igual que auth.routes.ts).

Respuesta exitosa (201):
{
  "token": "...",
  "user": { id, clinicId, branchId, firstName, lastName, email, role, active },
  "clinic": { id, name, nit, phone, email, address, city, plan, ... }
}

Errores:
- 400 si faltan campos requeridos
- 409 si el email de clínica o el email de admin ya existen
- 500 si error de BD

Exportar como: export const CLINIC_ROUTES = router;

  finishOnboarding() {
    if (this.saving()) return;
    this.saving.set(true);
    this.errorMsg.set('');

    // Separar nombre completo del admin en firstName y lastName
    const nameParts = this.vetName().trim().split(' ');
    const adminFirstName = nameParts[0] || 'Admin';
    const adminLastName = nameParts.slice(1).join(' ') || 'VetPro';

    const payload = {
      clinicName: this.clinicName(),
      nit: this.nit(),
      phone: this.phone(),
      email: this.vetEmail(),       // email de la clínica = email del admin
      address: this.branchAddress(),
      city: this.city(),
      branchName: this.branchName(),
      branchAddress: this.branchAddress(),
      adminFirstName,
      adminLastName,
      adminEmail: this.vetEmail(),
      adminPassword: this.adminPassword()
    };

    this.api.post<{ token: string; user: any; clinic: any }>(
      '/clinics/register', payload
    ).subscribe({
      next: (res) => {
        localStorage.setItem('vetpro_token', res.token);
        this.currentStep.set(4);
        this.saving.set(false);
      },
      error: (err) => {
        const msg = err?.error?.error || 'Error al registrar la clínica. Intenta de nuevo.';
        this.errorMsg.set(msg);
        this.saving.set(false);
      }
    });
  }

3.2 Configurar secretos de GitHub Actions
────────────────────────────────────────────────────────────────────────────────

En GitHub → Settings → Secrets → Actions, agregar:

  SSH_HOST        → IP o dominio del servidor de producción
  SSH_USER        → usuario SSH (ej: djfa)
  SSH_PORT        → puerto SSH (ej: 22)
  SSH_PRIVATE_KEY → llave privada SSH completa (incluye -----BEGIN/END-----)
  REGISTRY        → registro de Docker (ej: ghcr.io/daniel-jfa)
  REGISTRY_USER   → usuario del registro
  REGISTRY_TOKEN  → token de acceso al registro Docker
